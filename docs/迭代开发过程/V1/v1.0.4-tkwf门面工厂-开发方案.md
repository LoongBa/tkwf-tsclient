## 一、背景与目标

### 1.1 痛点

在 Web 项目中使用 `@tkwf/tsclient` 时，每个页面需要重复：

```typescript
const host = DomainHostClient.init("my-app", { endpoint: "/graphql" })
  .onGlobalError(handler)
  .onSign(signHandler);
const user = host.GetUser();
const api = user.Use<IApi>();
```

没有统一的入口管理，每页重复初始化代码，错误处理散落在各页面。

### 1.2 目标

提供一个**集中配置 + 一行调用**的静态门面工厂，将 SDK 的初始化、配置、会话管理、错误处理统一收敛到一处，简化 Web 项目的使用体验。

### 1.3 关键设计决策

| 决策 | 结论 |
|------|------|
| 命名 | `Tkwf` 静态门面（后端一致性，全栈开发者易理解） |
| 返回风格 | `await` + `onSuccess/onError` 并存，想用哪种用哪种 |
| `.Call()` | 移除（Use 已覆盖全部能力） |
| User/Guest | Level 0——只区分"是否预先验证"，不区分可调用的方法类型 |
| 约束 | 运行时 `assertConfigured()`，未配置时抛清晰错误 |
| User 无 session | 触发 `onUnauthorized` 钩子 + 抛 `AUTH_REQUIRED` |
| Guest | 不验证，直接调，服务端定论 |
| 门面位置 | 放进 `@tkwf/tsclient` SDK 包 |

项目模板参考：

```typescript
// 项目入口 app.ts
import { Tkwf } from "@tkwf/tsclient";

Tkwf.configure("default", {
  endpoint: "/graphql",
  storage: localStorage,
  onUnauthorized: () => {
    window.location.href = "/login";
  },
  onGlobalError: (err) => {
    showToast(err.message);
  },
});
```

## 三、方案设计

### 3.1 TkwfConfig 接口

```typescript
export interface TkwfConfig extends DomainHostClientOptions {
  onUnauthorized?: () => void;
  onSign?: SignHandler;
  onRequest?: (req: RequestContext) => void | RequestContext | Promise<RequestContext | void>;
  onResponse?: (res: ResponseContext, req: RequestContext) => void;
  onPong?: { intervalMinutes: number; handler: PongHandler };
  onGlobalError?: HostGlobalErrorHandler;
}
```

### 3.2 Tkwf 门面类

- 纯静态类，私有构造函数禁止实例化
- `configure(name, opts)`：创建 `DomainHostClient`、注册钩子、存入 Map
- `User` getter：取 `"default"` 场景 → `host.GetUser()` → 无 session 时触发 `onUnauthorized` + 抛异常
- `Guest` getter：取 `"default"` 场景 → `host.GetGuest()`
- `GetUser(scenario)` / `GetGuest(scenario)`：多场景切换
- `reset()`：清空所有场景（测试/热重载用）
- `assertConfigured()`：运行时守卫，未配置时抛清晰错误

### 3.3 移除 `.Call()`

| 删除目标 | 文件 |
|---------|------|
| `DomainClientUser.Call()` | `domain-client-user.ts` |
| `ServiceProxy.createCall()` | `service-proxy.ts` |
| `ChainableBuilder` 类 | `chainable.ts` |
| `ChainableBuilder` 导出 | `index.ts` |
| 相关测试 | `chainable.test.ts`, `service-proxy.test.ts` |

## 四、审核要点

1. 约束守卫是否生效：User/Guest 在 configure() 之前访问是否抛错
2. User 无 session 时的行为：onUnauthorized 是否触发，AUTH_REQUIRED 是否抛出
3. 多场景隔离：不同场景的 host 和钩子是否独立
4. 移除 `.Call()` 是否彻底：无残留引用
5. 测试覆盖：约束、基本功能、多场景各 3+ 个测试

---

## 五、代码纪律

- 不新增 `as any` / `@ts-ignore` / `@ts-expect-error`
- 所有 `transport.execute()` 调用必须显式提供 `selection` 参数
- 修改后必须 `npm test` + `npm run build`
- 不允许留下未使用的导出或死代码
