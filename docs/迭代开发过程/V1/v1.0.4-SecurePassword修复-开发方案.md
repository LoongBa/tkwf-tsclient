# v1.0.4 SecurePassword 修复与枚举值对齐

> **版本**：v1.0.4
> **背景**：V4.9.24 框架侧认证重构（authType 路由基座、约定式 SecurePassword、NullCredentialProtector）完成后，ts-client 在 DMP-Lite 集成验证中暴露了多个与 GraphQL schema 不匹配的问题。本迭代集中修复 SecurePassword 登录全链路的错误。
> **状态**：**实施完成**（2026-08-11）
> **关联文档**：`TKWF/docs/D02-多形态客户端认证架构.md`（v1.5）、`TKWF/docs/02-迭代开发/V4/v4.9.24-认证重构-开发方案.md`

---

## 1. 目标

1. **枚举值格式对齐**：TS client 发送的 `EnumLoginAuthType`/`EnumLoginFrom` 枚举值改为 SCREAMING_SNAKE_CASE（HotChocolate 默认序列化格式），匹配服务端 GraphQL schema。
2. **匿名登录请求修复**：`loginByContext` 移除 `sessionKey` 参数，避免 `HttpAuthenticationMiddleware` 拦截（后改为服务端排除 `/graphql` 路径，TS 侧回退）。
3. **`registerSecure` 类型修复**：`clientHash` 字段由 `Uint8Array` 转为 hex `string`，匹配 `RegisterSecureInput` 的 `String!` 类型。
4. **`variableTypes` 支持**（v1.0.3）：新增 `variableTypes` 参数，支持显式声明复杂输入类型的 GraphQL 类型，避免 `inferGraphQLType` 对 object 退回 `JSON`。
5. **错误详情区分**：DMP-Lite 侧新增 `extractLoginError()`，区分客户端/服务端错误来源。

## 2. 变更清单

### 2.1 枚举值对齐（SCREAMING_SNAKE_CASE）

**问题**：TS client 发送 `loginByContext` 时使用 PascalCase 枚举值（`PcWeb`、`Password`、`SecurePassword`），但 HotChocolate 默认将 .NET 枚举序列化为 SCREAMING_SNAKE_CASE（`PC_WEB`、`PASSWORD`、`SECURE_PASSWORD`），导致 GraphQL 报错 `EnumLoginFrom cannot coerce the given value`。

**修复**：`src/domain-client-user.ts` 中所有硬编码枚举值改为 SCREAMING_SNAKE_CASE：

| 位置 | 行 | 旧值 | 新值 |
|------|-----|------|------|
| `loginByContext` 默认 | 207 | `"PcWeb"` | `"PC_WEB"` |
| `loginByContext` 默认 | 208 | `"Password"` | `"PASSWORD"` |
| `loginSecure` 调用 | 274 | `"SecurePassword"` | `"SECURE_PASSWORD"` |

**同步修改**：`transport.test.ts`、`domain-client-user.test.ts` 中的测试用例枚举值。

### 2.2 `loginByContext` 匿名登录修复

**问题**：`loginByContext` 调用时传了 `sessionKey: this.sessionKey ?? undefined`。当用户有 guest 会话时，`this.sessionKey` 非空，`BaseHttpTransport` 添加 `X-Session-Key` header。服务端 `HttpAuthenticationMiddleware` 检测到 session key 但用户未认证（guest），返回 401 `AUTH_REQUIRED`。

**初始修复**（v1.0.4-rc1）：移除 `sessionKey` 参数，与 `loginByPassword`/`loginBySms` 一致。

**后续修复**（服务端侧）：`HttpAuthenticationMiddleware` 排除 `/graphql` 路径，GraphQL 操作的认证由 AOP `[AllowAnonymousFlag]` 控制。TS 侧回退 cookie hack。

**最终方案**（服务端）：`DMP-Lite.Merchant.WebApi/Program.cs` 中 `HttpAuth.SetExcludedPathPrefixes` 加入 `/graphql`。

### 2.3 `registerSecure` clientHash 类型修复

**问题**：`AuthCrypto.pbkdf2()` 返回 `Uint8Array`（32 字节原始字节），但 `RegisterSecureInput.clientHash` 期望 `String`（hex 编码）。`registerSecure` 直接将 `Uint8Array` 传给 GraphQL，导致 `String cannot coerce the given value JSON element of type Object`。

**修复**：`src/domain-client-user.ts` 中 `registerSecure` 方法，`clientHash` 经 `bytesToHex()` 转为 hex 字符串后再发送：

```diff
- const clientHash = await cryptoImpl.pbkdf2(password, salt, iters);
+ const clientHashBytes = await cryptoImpl.pbkdf2(password, salt, iters);
+ const clientHash = cryptoImpl.bytesToHex(clientHashBytes);
```

### 2.4 `variableTypes` 参数（v1.0.3）

**问题**：`transport.execute()` 发送复杂输入类型（如 `LoginContextInput`）时，`inferGraphQLType()` 对 object 只能推断为 `JSON`，但服务端 schema 期望具体类型名（如 `LoginContextInput!`）。

**修复**：`Transport` 接口 + `execute()` 新增 `variableTypes?: Record<string, string>` 参数，显式声明变量 GraphQL 类型，覆盖 `inferGraphQLType` 的自动推断。

```typescript
// 新增 variableTypes 参数
variableTypes: { input: "LoginContextInput!" },
variables: { input: { userName, credential, ... } },
```

### 2.5 `selection` 补充（v1.0.2）

**问题**：`loginAs` 内部 `loginSecure` 方法用 `transport.execute()` 直接调用 `requestChallenge` 和 `registerSecure`，未传 `selection` 参数，绕过了 `ServiceProxy` 的 `selectionMap`，导致 GraphQL 查询缺少子字段选择。

**修复**：
- `requestChallenge` 调用补充 `selection: "challengeToken salt iterations"`
- `registerSecure` 调用补充 `selection: "success message"`

## 3. 测试要点

| 测试 | 说明 |
|------|------|
| `loginByContext` 枚举值 | 发送 `PC_WEB`/`SECURE_PASSWORD`，服务端正确解析 |
| `loginByPassword` 枚举值 | 不涉及枚举，直接传 `userName`/`password` 字符串 |
| `loginBySms` 枚举值 | 不涉及枚举，直接传 `mobile`/`captcha` 字符串 |
| `registerSecure` clientHash | 发送 hex string，服务端正确接收 |
| `loginByContext` 无 sessionKey | 不传 `X-Session-Key` header，服务端 `HttpAuthenticationMiddleware` 放行 |
| `variableTypes` 覆盖 | 复杂输入类型使用显式类型声明，非 `JSON` |
| `requestChallenge` selection | 查询包含 `challengeToken salt iterations` 子字段 |
| `registerSecure` selection | 查询包含 `success message` 子字段 |
