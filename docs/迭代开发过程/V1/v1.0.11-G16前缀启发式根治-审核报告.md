## 一、概述

G16 根因三层：① 服务端 SG `IsMutationMethod` 把 `Xxx_ExecuteAsync` 判为非 mutation → 所有 `*_Execute` 字段进 GraphQL Query 根（**稳定事实**，P1 方案 Oracle 已否决框架侧改动）；② SDK `MUTATION_PREFIXES` 前缀启发式把 `remove*/create*` 判为 mutation → 发 `mutation { removeBuddy_Execute }` → 服务端 Mutation 根无此字段 → HTTP 400；③ **根因锚点**：消费端 codegen 产物 `ts-client.g.ts` 已生成正确 `type:'query'|'mutation'` 标记，但 SDK 完全不消费。

**修复方向（按 TKWF 设计原则重构为全局最优解）**：SDK 收敛为**纯消费方**——新增 `operationKinds` 单映射（`Record<string, 'query'|'mutation'>`，codegen 权威产物）作为最高优先级判定源；`MUTATION_PREFIXES` 启发式降为废弃兜底（命中即单次 console.warn，可 `suppressHeuristicWarning` 关闭）；`explicitMutations` 保留为未接线向后兼容兜底。对齐设计原则 **P1 编译期优先**（type 判定在生成期确定）、**P2 唯一权威源**（schema 根类型 → 生成器 → operationKinds → SDK 纯消费，启发式废弃）、**P7 不静默失效**（废弃路径显式告警）。服务端 `_TKWF` 零改动。

## 五、设计原则符合性

| 原则 | 落地 |
|------|------|
| **P1 编译期确定性优先于运行时反射** | type 判定由 codegen 在生成期权威确定（`buildOperationKinds` ← schema 根类型 `ParsedOperation.kind`），SDK 运行时纯读取零猜测 |
| **P2 唯一权威事实源，下游纯消费** | 单一链路：schema 根类型 → 生成器 → `operationKinds` → SDK；启发式废弃，explicitMutations 仅未接线兜底 |
| **P7 缺省=守卫硬失败，不静默失效** | 启发式（废弃路径）实际被使用即 `console.warn` 单次（可 suppress）——废弃路径显式暴露 |
| 错误模式"脆弱启发式替代契约" | `MUTATION_PREFIXES` 前缀启发式废弃（对齐 ADR94 G20 权威注册契约化先例） |
| 元原则"先例可能错" | explicitQueries 双集合方案重构为 operationKinds 单映射——以全局最优为判据，非迁就既有逃生口 |
