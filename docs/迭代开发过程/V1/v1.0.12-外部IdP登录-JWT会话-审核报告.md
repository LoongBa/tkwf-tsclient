## 一、概述

SDK 登录族（loginAs/loginBySms/loginByContext/loginSecure）全部基于 GraphQL `sessionKey` 会话模型，无外部 IdP 登录 API、无 JWT 会话承载、无 Bearer 携带、无 refresh 续期。认证中心已发布 `POST /api/auth/login/external/{channelType}` → `TokenResponse`（JWT，wire **camelCase**）端点族，前端对接存在三类缺口：① 无 `loginByExternal` 方法；② `LoginPayload` 的 JWT 字段（accessToken/refreshToken/expiresAt）拿到即弃（persist/restore 仅认 sessionKey）；③ 无 OAuth 回调辅助。

**修复方向（按 TKWF 设计原则重构为全局最优解）**：SDK 新增三件核心能力——

1. **外部 IdP 登录**：`loginByExternal(channelType, parameters)` 经 **REST 专用能力通道**（`Transport.loginByExternal?` 可选方法，P3 能力即注册，仅 RestTransport 实现）消费 AuthCenter 端点族，URL 复用既有 `urlMap` 单一解析 + `{channelType}` 模板 `encodeURIComponent`（M3/S2）；GraphQL 主传输经 `externalLoginTransport` 注入式兜底（N1）。
2. **JWT 会话模型**：独立 `externalSession{accessToken/refreshToken/expiresAt(unix ms)}` 字段与 sessionKey 并列，形态即字段存在性（零 flag 判别，M4）；`persist`/`restore` 双形态、`restore` sessionKey 优先（旧数据零回归）；**N3 互斥不变量**——两形态至多一个非 null；`refreshJwt()` 显式续期（P5，错误分层：refresh 4xx → `JWT_SESSION_INVALID` 清会话 / access 401 → `AUTH_EXPIRED` 可续，M7）。
3. **Bearer 携带**：4 处注入点（GraphQLTransport.execute / executeRawGraphQL / RestTransport.execute / uploadFile）+ ServiceProxy 透传 + Use/query/mutate/ping/logout/Query 六路径（M6）。
4. **OAuth 回调辅助**：`resolveOAuthCallback` 为 `QueryString.parse` 预设（S3），删除 buildExternalLoginUrl（M2/M5——Federation 服务端已提供权威 `authorize_url`，客户端拼 URL 违反 P2）。

对齐设计原则：**P2 唯一权威源**（服务端 TokenResponse wire 契约 1:1 → ExternalLoginResult 严格 4 字段；urlMap 单一 URL 解析）、**P5 显式决策**（refresh 显式续期，无自动隐式魔法；storage 策略显式文档化）、**P7 守卫硬失败**（前置守卫 channelType/code/ticket + 响应缺 accessToken → JWT_SESSION_INVALID + 无通道 → EXTERNAL_LOGIN_FAILED）、**P10 生成物防绕过**（`generated/error-codes.ts` 零改动，客户端码入 domain-client-error.ts union）。

## 五、设计原则符合性

| 原则 | 落地 |
|------|------|
| **P1 编译期确定性优先于运行时反射** | `loginByExternal` 经 `Transport.loginByExternal?` 编译期固定能力方法（P3 能力即注册），不经 ServiceProxy 运行时前缀启发式；URL 经 urlMap 单一解析 + 模板编译期注入 |
| **P2 唯一权威事实源，下游纯消费** | 服务端 TokenResponse wire（camelCase）→ `ExternalLoginResult` 严格 4 字段 1:1（不含 userName/displayName——N2）；urlMap 单一 URL 解析（删 externalLoginEndpoint——M3）；authorize_url 服务端权威（删除 buildExternalLoginUrl——M2/M5）；externalSession 独立字段零 flag（删 isJwtSession——M4） |
| **P5 显式决策优于自动行为** | `refreshJwt()` 显式续期（无自动隐式 refresh 魔法）；storage 策略显式文档化（M8）；REST 通道配置显式注入（N1） |
| **P7 缺省=守卫硬失败，不静默失效** | 前置守卫（channelType/code||ticket）→ INVALID_ARGUMENT；无通道 → EXTERNAL_LOGIN_FAILED；响应缺 accessToken → JWT_SESSION_INVALID；refresh 失效 → 清会话（CM1） |
| **P8 领域自治与框架管理边界** | OAuth 平台知识（scope/snsapi_base）不进 SDK（删除 buildExternalLoginUrl）；登录挂 Guest 语义 |
| **P10 生成物防绕过** | `generated/error-codes.ts` 零改动（M10/CM 验收），客户端码入 domain-client-error.ts union |
| **P9 零新增依赖** | 无新第三方依赖；resolveOAuthCallback 委托既有 QueryString.parse（S3） |
| 元原则"先例可能错" | 不因"现有登录都是 sessionKey"否定 JWT 会话；不因"现有 URL 解析"引入 externalLoginEndpoint 第二套机制——以认证中心冻结契约为判据 |

## 六、向后兼容

- 全部新增项可选：不配置 `externalLoginTransport`/`restUrlMap["loginByExternal"]`/不调用新 API → v1.0.11 行为零回归（331 基线全绿）
