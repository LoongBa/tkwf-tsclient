# v1.0.15：开放业务码透传（REST 错误体 `{"error":"<code>"}`）

> **来源**：DMP-Lite 公众号图文一键登录迭代（2026-11-10 复查 P1-4 缺口）——免登录/领卡建档端点的业务错误码（`TICKET_INVALID`/`configuration_invalid`/`channel_mismatch`/`member_disabled`/`register_token_invalid` 等）在 SDK 层被丢弃，前端错误文案全部回落兜底。
> **类型**：小修复（2 文件 + 测试），patch 升级 v1.0.14 → v1.0.15。

---

## 1. 问题实证

- `toErrorCode`（`src/domain-client-error.ts`）：仅 401 分支解析 `body.errorCode`（固定两码 AUTH_*），400 分支仅认 `body.errorCode` 两个固定值（INVALID_ARGUMENT/JWT_SESSION_INVALID）；**不认 `body.error`（string）字段且无开放透传** → DMP 后端错误体 `{"error":"channel_mismatch","message":"..."}` 解析后回落 `UNKNOWN`。
- `base-http-transport.ts` L118-120：`!response.ok` 分支调用 `toErrorCode(response.status)` **未传 bodyText** → 即使解析逻辑支持也拿不到响应体（401 分支已传、此处遗漏）。

## 2. 方案（最小改动、兼容性优先）

| 文件 | 改动 |
|---|---|
| `src/domain-client-error.ts` | `toErrorCode` 末尾（固定状态映射 + GraphQL 解析**之后**、返回 UNKNOWN 之前）新增：`body.error` 为 string 且非空时**原样透传**（`as ErrorCode` 断言声明开放集语义） |
| `src/base-http-transport.ts` | `!response.ok` 分支改为 `toErrorCode(response.status, undefined, bodyText)` |
| `src/domain-client-error.test.ts` | +4 组用例：400 透传 / 404 固定优先 / 403·429·5xx 固定优先 / 非 string·缺失·非 JSON 回落 UNKNOWN |

**兼容性论证**：
- 透传置于固定映射之后 → 401/403/404/409/429/5xx 行为零变化（测试锁定）；
- 仅"未知码"场景（现返回 UNKNOWN）受益：非 4xx/5xx 固定码的 400 等，若 body 给出业务码则透传，否则仍 UNKNOWN；
- GraphQL 通道：非 200 错误响应体为 `{"errors":[...]}`（无 `error` 字段），不透传；200 + extensions.code 路径不受影响；
- 运行时 `err.code` 可为任意业务码（联合类型无法穷举开放集，断言声明；调用方按 string 消费）。
