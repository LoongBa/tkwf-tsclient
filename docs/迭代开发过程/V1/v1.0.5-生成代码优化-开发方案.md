# v1.0.5 生成代码优化（基类化 + 泛型化 + 映射类型派生）

> **版本**：v1.0.5
> **背景**：ts-client.g.ts 生成文件已达 4312 行，其中 42.7%（QueryBuilder 类型区）与 43.4%（Schema 类型区）存在大量**结构同构的重复**。对标服务器端 `DomainReadOnlyDataServiceBase` / `DomainDataServiceBase` 泛型基类模式（实体 Service 只需继承 + 写差异），TS 端生成代码可通过 **SDK 基类收拢通用实现 + 泛型/映射类型收拢同构类型** 同等压缩。
> **状态**：待开发
> **方案修订**：2026-08-12（v1 审核修正：FilterInput 分族泛型化、操作符工厂移 SDK、预期重估）

---

## 一、目标

1. **消除重复生成的通用实现**：`compileGraphQL` / `createOrderByProxy` 移入 SDK `QueryBuilderBase` 具体实现（当前声明 `abstract` 却逐实体复制相同内容）
2. **同构类型泛型化**：`OperationFilterInput` 家族（5 数值/日期 + 1 String + 1 Boolean + 13 枚举）、`Connection`/`Edge` 收拢为 SDK 泛型类型 + 生成端类型别名
3. **同构类型映射派生**：`SelectFields` / `OrderByFields` 从 Fields 接口用 `keyof` + 映射类型派生，不再逐实体平铺
4. **createFieldsProxy 元数据驱动**：switch-case 逐字段展开改为字段元数据表驱动（proxy 外壳逻辑 + 操作符工厂函数移入 SDK 基类）
5. **预期：4312 行 → ~2900 行（减 ~33%）**，且不改动任何对外 API 语义（纯内部重构）

## 三、变更设计

### 3.1 SDK：`QueryBuilderBase` 收拢通用实现（核心）

**现状**（`tkwf-tsclient/src/query-builder.ts` L330-336）：

```typescript
protected abstract compileGraphQL(): string;      // L332
protected abstract createFieldsProxy(): TFields;   // L333
protected abstract createOrderByProxy(): TOrderByFields;  // L334
protected abstract defaultFields(): string[];      // L336
```

**生成代码**（`DMP-Lite/scripts/gen-ts-client.ts` L1112-L1125 等）逐实体重复生成：

```typescript
protected compileGraphQL(): string {
  const fields = this._fields.length > 0
    ? this._fields.join(" ")
    : this.defaultFields().join(" ");
  const whereClause = this.buildWhereClause();
  const orderClause = this.buildOrderClause();
  const afterClause = this._afterCursor ? `, after: "${this._afterCursor}"` : "";
  const pageInfo = this._cursorCache.size > 0 || this._afterCursor
    ? " pageInfo { endCursor hasNextPage }" : "";
  return `query { ${this.resolverField}(first: ${this._pageSize}${afterClause}${whereClause}${orderClause}) { totalCount nodes { ${fields} }${pageInfo} } }`;
}
```

**问题**：该实现只使用基类状态（`_fields` / `_afterCursor` / `_cursorCache` / `resolverField` / `_pageSize`）与基类方法（`defaultFields()` / `buildWhereClause()` / `buildOrderClause()`），**无任何实体特有逻辑**——却作为 `abstract` 要求每个实体子类复制一份。

**改法**：

```typescript
// SDK query-builder.ts：compileGraphQL 改为具体实现（原 abstract L332）
protected compileGraphQL(): string {
  const fields = this._fields.length > 0
    ? this._fields.join(" ")
    : this.defaultFields().join(" ");
  const whereClause = this.buildWhereClause();
  const orderClause = this.buildOrderClause();
  const afterClause = this._afterCursor ? `, after: "${this._afterCursor}"` : "";
  const pageInfo = this._cursorCache.size > 0 || this._afterCursor
    ? " pageInfo { endCursor hasNextPage }" : "";
  return `query { ${this.resolverField}(first: ${this._pageSize}${afterClause}${whereClause}${orderClause}) { totalCount nodes { ${fields} }${pageInfo} } }`;
}

// createOrderByProxy 同样改为具体实现（原 abstract L334）
protected createOrderByProxy(): TOrderByFields {
  return new Proxy({} as TOrderByFields, {
    get: (_t: any, prop: string | symbol) => {
      const field = typeof prop === "string" ? prop : "";
      const self: SortNode = { field, isDesc: false, asc: dummyAsc, desc: dummyDesc };
      return self;
    },
  });
}
```

`compileGraphQL` / `createOrderByProxy` 从 `abstract` 改为**具体实现**；`defaultFields` 仍保留 `abstract`（实体差异）；`createFieldsProxy` 保留 `abstract`（字段元数据是实体差异，见 3.5）。

**生成端**（`gen-ts-client.ts`）：不再输出 `compileGraphQL` / `createOrderByProxy` 方法体。

**收益**：去掉 286 行重复 + 生成模板简化。

### 3.2 SDK：`OperationFilterInput` **分族**泛型化

**⚠️ 实测结论（v1 修订）**：5 个数值/日期标量同构，但 **String 与 Boolean 字段集不同构**，必须分族设计——不能用一个 `OperationFilterInput<T>` 覆盖全部标量：

| 族 | 成员 | 字段集 |
|----|------|--------|
| 数值/日期 | Long / Int / Decimal / DateTime / LocalDate | eq, neq, in, nin, gt, ngt, gte, ngte, lt, nlt, lte, nlte |
| 字符串 | String | and, or, eq, neq, contains, ncontains, in, nin, startsWith, nstartsWith, endsWith, nendsWith |
| 布尔 | Boolean | eq, neq |
| 枚举 | 13 个 `XxxEnumOperationFilterInput` | eq, neq, in, nin |

**改法**（SDK `query-builder-types.ts` 新增 4 个泛型/接口）：

```typescript
// 数值/日期族（12 操作符；in/nin 沿用现有单值语义，与实测 ts-client.g.ts 一致）
export interface OperationFilterInput<T> {
  eq?: T | null; neq?: T | null; in?: T | null; nin?: T | null;
  gt?: T | null; ngt?: T | null; gte?: T | null; ngte?: T | null;
  lt?: T | null; nlt?: T | null; lte?: T | null; nlte?: T | null;
}

// 字符串族（12 成员，无数值比较）
export interface StringOperationFilterInput {
  and?: StringOperationFilterInput | null;
  or?: StringOperationFilterInput | null;
  eq?: string | null; neq?: string | null;
  contains?: string | null; ncontains?: string | null;
  in?: string | null; nin?: string | null;
  startsWith?: string | null; nstartsWith?: string | null;
  endsWith?: string | null; nendsWith?: string | null;
}

// 布尔族（仅 eq/neq）
export interface BooleanOperationFilterInput {
  eq?: boolean | null;
  neq?: boolean | null;
}

// 枚举族（4 操作符，值类型为字符串字面量联合）
export interface EnumOperationFilterInput<T extends string> {
  eq?: T | null; neq?: T | null; in?: T | null; nin?: T | null;
}
```

> ⚠️ 兼容性注意（**实测确认**）：现有生成接口的 `in`/`nin` 为**单值** `string | null` / `number | null`（非数组），且字段为必选（无 `?`）。本方案转 SDK 泛型时**沿用单值语义**（`in?: T | null`）但**把字段改为可选 `?`**——可选化是安全的方向（赋值场景全部兼容，读取场景由操作符语义保证）；若要求字段严格保持必选，去掉 `?` 即可，不影响结构兼容。是否顺手修正为数组语义（HC 惯常）需单独决策，见 3.6 风险。

**生成端**（`gen-ts-client.ts`）：20 个平铺接口 → 20 行类型别名：

```typescript
export type LongOperationFilterInput = OperationFilterInput<number>;
export type IntOperationFilterInput = OperationFilterInput<number>;
export type DecimalOperationFilterInput = OperationFilterInput<number>;
export type DateTimeOperationFilterInput = OperationFilterInput<string>;
export type LocalDateOperationFilterInput = OperationFilterInput<string>;
export type CouponVerificationStatusEnumOperationFilterInput = EnumOperationFilterInput<"NONE" | "PENDING" | ...>;  // 枚举字面量联合来自 schema enum
// String/Boolean 族 SDK 已定义，无需别名（原有接口名即 SDK 类型名）
```

**收益**：FilterInput 区 **158 行 → ~53 行（4 SDK 接口 ~35 行 + 18 别名）**，净省 **~105 行**。因 String/Boolean 需独立接口，收益小于初稿预估（原误算 150）。

### 3.3 SDK：`Connection` / `Edge` 泛型化

**现状**：7 个 Connection + 7 个 Edge，字段完全同构。

**改法**（SDK `query-builder-types.ts`）：

```typescript
export interface Connection<TNode, TEdge> {
  pageInfo: PageInfo;
  edges: Array<TEdge>;
  nodes: Array<TNode>;
  totalCount: number;
}
export interface Edge<TNode> {
  cursor: string;
  node: TNode | null;
}
```

**生成端**：

```typescript
export type CouponReconLogConnection = Connection<CouponReconLog, CouponReconLogEdge>;
export type CouponReconLogEdge = Edge<CouponReconLog>;
```

**收益**：70 行 → ~18 行，净省 ~52 行。

### 3.4 生成端：`SelectFields` / `OrderByFields` 映射类型派生

**现状**：每实体平铺 `Partial<{ field: true; ... }>`（35 行）与 `{ field: SortNode; ... }`（33 行）。

**改法**（SDK 提供映射类型，生成端一行别名）：

```typescript
// SDK query-builder-types.ts
export type SelectFieldsOf<TFields> = Partial<Record<keyof TFields, true>>;
export type OrderByFieldsOf<TFields> = Record<keyof TFields, SortNode>;
```

**生成端**：

```typescript
export type CouponReconLogSelectFields = SelectFieldsOf<CouponReconLogFields>;
export type CouponReconLogOrderByFields = OrderByFieldsOf<CouponReconLogFields>;
```

**收益**：884 行 → ~30 行（13 别名 × 2 + 2 SDK 类型），**净省 ~850 行（最大单项）**。

> 注意：`SelectFields` 语义与现有 `Partial<{...}>` 完全等价（`keyof Fields` = 可过滤标量字段集）；`OrderByFields` 同理。实体私有嵌套字段不会泄漏（Fields 接口本身已限定标量集）。

### 3.5 生成端：`createFieldsProxy` 元数据驱动 + 操作符工厂上移 SDK

**现状**：248 个 switch-case（每实体 ~31 个 case + 7 行外壳）。

**改法**：**前置动作**——把生成在 ts-client.g.ts 文件头的操作符工厂函数（L2478-2539，62 行）**上移 SDK**（`query-builder.ts`），因为外壳逻辑进入 SDK 基类后必须能引用它们：

```typescript
// SDK query-builder.ts 新增：createOperators / createStringOps / createNumberOps /
// createDateOps / createBooleanOps / dummyAsc / dummyDesc（现 ts-client.g.ts L2478-2539 原样迁移）
// 它们依赖 LeafNode（已在 SDK），不依赖任何生成类型
```

**然后** SDK 基类新增元数据外壳辅助：

```typescript
// SDK query-builder.ts
protected createFieldsProxyFrom<T>(meta: Record<string, string>): T {
  return new Proxy({} as T, {
    get: (_t: any, prop: string | symbol) => {
      const fieldName = typeof prop === "string" ? prop : "";
      const gqlType = meta[fieldName];
      if (!gqlType) throw new Error(`Unknown field '${fieldName}'`);
      return createOperators(fieldName, gqlType, proxy);
    },
  });
}
```

**生成端**（每实体）：

```typescript
protected createFieldsProxy(): CouponReconLogFields {
  return this.createFieldsProxyFrom<CouponReconLogFields>({
    id: "Long", uId: "String", orderTime: "DateTime", /* ... 每字段 1 行 */
  });
}
```

**收益**：Proxy 外壳（91 行）+ 操作符工厂（62 行）移入 SDK，生成端每实体只留「字段→gqlType」元数据（每字段 1 行，运行时必需，不省）。**净省 ~153 行**。

### 3.6 保留不动（明确边界）

| 项 | 原因 |
|----|------|
| **Schema DTO 接口区**（实体接口平铺） | 契约事实，是 schema 定义的真实反映，无法收拢（每实体字段不同） |
| **Fields 接口**（13 个，各 33 行 = 429 行） | 字段→操作符类型的精确映射（String 有 contains、Date 无），纯 `keyof` 映射无法区分 String 与 DateTime（TS 皆为 string），保留平铺 |
| **Service 接口 / 常量 / 分组** | 已精简（每 Service ~6 行） |
| **createFieldsProxy 的元数据表** | 字段名 + gqlType 是运行时必需元数据，仅变换表现形式（case → 对象字面量） |

### 3.7 风险决策点（需用户确认）

| # | 决策点 | 选项 A（推荐，本方案默认） | 选项 B |
|---|--------|---------------------------|--------|
| R1 | FilterInput 的 `in`/`nin` 字段：现状为**单值**（`in: string \| null`），HC 语义惯常为数组 | 保持单值，零行为变化（等价性测试简单） | 顺手修正为数组 `T[]`（行为变更，需同步检查消费端传参） |
| R2 | FilterInput 转 SDK 泛型后字段加 `?`（可选化） | 可选化：赋值兼容全部现有场景 | 保持必选（去 `?`）：结构严格一致，但 API 更脆 |

> 本方案默认 R1=A、R2=可选化（安全方向）。若选 R1=B，则编码层需额外回归；建议本次迭代不做，另立项。|
