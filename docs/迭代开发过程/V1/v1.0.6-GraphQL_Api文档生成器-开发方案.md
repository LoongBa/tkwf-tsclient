# v1.0.6 GraphQL_Api.md 文档生成器

> **版本**：v1.0.6
> **背景**：前端 Agentic Coding 场景中，schema.graphql（~3700 行）噪音大、ts-client.g.ts（~1400 行）字段树 token 轰炸、Domain_Api.md 含 C# 残留无法直接消费。需新增一份面向「前端+Agent」的活态契约文档 `GraphQL_Api.md`，与 `ts-client.g.ts` 同源、同步、同脚本生成。
> **状态**：待开发
> **方案依据**：`docs/codegen/GraphQL_Api.md-设计方案.md`（v1.1 自查修订版）
> **方案修订**：2026-08-14

---

## 一、目标

1. **新增 `src/codegen/` 模块**：提供 `parseGraphQLSchema()` + `generateGraphQLApiDoc()` 两个核心导出，零侵入主 SDK 运行时
2. **一次解析，双产物输出**：`parseGraphQLSchema()` 将 schema 解析为 `ParsedSchema` 中间模型，消费端可同时用于 `ts-client.g.ts` 和 `GraphQL_Api.md` 生成，避免二次解析
3. **渲染函数零 graphql 依赖**：`generateGraphQLApiDoc()` 只消费 `ParsedSchema` 纯数据，不 import `graphql` 包，消费端即使不装 graphql 也能手动构造 `ParsedSchema` 调用
4. **`graphql` 包作为 optional peerDependency**：SDK 运行时（`Tkwf.User.Use<T>()` 等）不依赖 graphql，仅 codegen 路径需要
5. **输出格式符合 RFC §4 规范**：操作概览、按域操作清单、DTO 字段速查、暴露状态与缺口、页面→操作映射五章节

## 三、变更设计

### 3.1 架构总览

```
消费端：parseGraphQLSchema(schemaText)          ← SDK 导出
                       │
                       ▼
                  ParsedSchema                      ← SDK 中间模型
                  ├─ operations: ParsedOperation[]
                  ├─ types: ParsedType[]
                  └─ source: string
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
  generateTsClient(parsed)  generateGraphQLApiDoc(parsed, options)
  (消费端自有，不在 SDK 范围)       (SDK 导出，本方案实现)
                                   │
                                   ▼
                          GraphQL_Api.md (markdown 字符串)
```

### 3.2 新增文件：`src/codegen/schema-parser.ts`

**导出类型**：

```typescript
export type GraphQLScalar = "String" | "Int" | "Float" | "Boolean" | "ID" | "Long"
  | "DateTime" | "LocalDate" | "Decimal" | "UUID" | "URL" | "Byte" | "JSON";

export interface ParsedArg {
  name: string;
  gqlType: string;
  isNonNull: boolean;
  isList: boolean;
  defaultValue?: string;
}

export interface ParsedOperation {
  name: string;
  kind: "query" | "mutation";
  args: ParsedArg[];
  returnType: string;
  returnIsList: boolean;
  returnIsNonNull: boolean;
  description?: string;
}

export interface ParsedField {
  name: string;
  gqlType: string;
  isNonNull: boolean;
  isList: boolean;
  description?: string;
  isScalar: boolean;
}

export interface ParsedType {
  name: string;
  kind: "object" | "interface" | "input" | "enum";
  fields: ParsedField[];
  enumValues?: string[];
  description?: string;
}

export interface ParsedSchema {
  operations: ParsedOperation[];
  types: ParsedType[];
  source: string;
}
```

**导出函数**：

```typescript
export function parseGraphQLSchema(schemaText: string): ParsedSchema;
```

**实现要点**：

1. 运行时动态 `import("graphql")`，不存在时抛友好错误
2. 调用 `graphql.parse(schemaText)` 得到 `DocumentNode`
3. 遍历 `definitions`：
   - `ObjectTypeDefinition` → `type XxxDto`、`type Query`、`type Mutation`
   - `InputObjectTypeDefinition` → `input XxxInput`
   - `InterfaceTypeDefinition` → `interface Xxx`
   - `EnumTypeDefinition` → `enum Xxx { A B C }`
4. Query/Mutation 识别：名称为 `Query` / `Mutation` 的 `ObjectTypeDefinition`
5. 标量判定：`SCALAR_SET` 白名单（String/Int/Float/Boolean/ID/Long/DateTime/LocalDate/Decimal/UUID/URL/Byte/JSON）
6. 描述提取优先级：`"""` 块 > `#` 注释 > `@cost` 指令参数 > 空字符串

### 3.3 新增文件：`src/codegen/graphql-api-doc.ts`

**导出类型**：

```typescript
export type ExposureStatus = "exposed" | "unexposed" | "missing" | "partial";

export interface GenerateGraphQLApiDocOptions {
  domainName?: string;
  ignoredFields?: Set<string>;
  exposureStatus?: Record<string, ExposureStatus>;
  pageMapping?: Record<string, string[]>;
  blockingPages?: Record<string, string>;
  descriptions?: Record<string, string>;
  groupOverrides?: Record<string, string>;
  scalarMap?: Record<string, string>;
}
```

**导出常量**：

```typescript
export const DEFAULT_SCALAR_TS_MAP: Record<string, string> = {
  String: "string", ID: "string", URL: "string", UUID: "string",
  Int: "number", Float: "number", Long: "number", Decimal: "number", Byte: "number", Short: "number",
  Boolean: "boolean",
  DateTime: "string", LocalDate: "string",
  JSON: "unknown",
};
```

**导出函数**：

```typescript
export function generateGraphQLApiDoc(
  parsed: ParsedSchema,
  options?: GenerateGraphQLApiDocOptions,
): string;
```

**内部处理流程**：

```
输入：ParsedSchema + Options
  │
  ├─ 1. 过滤类型：排除 Query/Mutation/Subscription 根类型
  │     → 排除 ignoredFields 中的字段
  │     → 标注 isScalar
  │
  ├─ 2. 操作→DTO 关联：追溯 returnType
  │     → 标量返回直接标注（如 `Boolean`）
  │     → DTO 返回在 DTO 速查表中建条目
  │
  ├─ 3. 业务域分组：按 heuristic + groupOverrides
  │     → 复用 MUTATION_PREFIXES 判断 mutation
  │     → 见 §3.5 分组规则
  │
  ├─ 4. 暴露状态标注：合并 schema 存在性 + exposureStatus
  │     → schema 有 且 未配置 = ✅ exposed
  │     → exposureStatus = 'unexposed' = 🔴 有契约未暴露
  │     → exposureStatus = 'missing' = 🔴 缺失
  │     → exposureStatus = 'partial' = 🟡 部分暴露
  │
  └─ 5. Markdown 渲染：五章节输出
      → 一、操作概览（域×分类统计）
      → 二、按域操作清单（核心表）
      → 三、DTO 字段速查（仅被引用的 DTO）
      → 四、暴露状态与缺口
      → 五、页面→操作映射（pageMapping 提供时输出，否则"待补充"）
```

### 3.4 Markdown 渲染格式

**文档标题**：

```markdown
# GraphQL API 契约 — 前端/Agent 消费版

> 自动生成（@tkwf/tsclient v1.0.6）｜生成时间：2026-08-14 12:00:00
> 源：schema.graphql（禁止手改；缺失/过时报告补齐）
```

**操作清单表（核心表）**：

```markdown
### 域：门店管理（store）

| GraphQL 操作 | 分类 | 说明 | 参数 (TS) | 返回 | 状态 |
|---|---|---|---|---|---|
| `listStores` | Query | 查询门店列表（分页+名称/主店过滤） | `{ name?: string; isMainStore?: boolean; page: number; pageSize: number }` | `StoreListResponseDto` | ✅ |
| `deleteStore` | Mutation | 删除门店 | — | `Boolean` | 🔴 缺失 |
```

**DTO 字段速查**：

```markdown
| DTO | 关键字段 |
|-----|---------|
| `StoreListResponseDto` | id, name, contactName, contactPhone, address, isMainStore |
| `StoreInfoDto` | id, name, address → 见 `AddressDto` |
```

### 3.5 业务域分组 heuristic

复用 `service-proxy.ts` 的 `MUTATION_PREFIXES`：

| 操作名模式 | 分组名 | 示例 |
|-----------|--------|------|
| `list*` / `get*` / `*ById` / `query*` + 业务词 | 提取业务词 | `listStores` → `store` |
| `create*` / `update*` / `delete*` / `remove*` / `add*` + 业务词 | 提取业务词 | `createStore` → `store` |
| `lock*` / `unlock*` / `reset*` + 业务词 | 提取业务词 | `resetPassword` → `password` |
| `login*` / `logout` / `ping` | `auth` | `loginByPassword` → `auth` |
| 无前缀匹配 | `other` | `dashboard` → `other` |
| `options.groupOverrides` 覆盖 | 自定义 | `{ listPaymentLogs: "payment-log" }` |

### 3.9 依赖策略关键细节

- `parseGraphQLSchema()` 内部使用动态 `import("graphql")`，不存在时抛出友好错误
- `generateGraphQLApiDoc()` 不 import 任何 `graphql` 类型，只接受 `ParsedSchema`（纯数据接口）
- `ParsedSchema` 及其子类型不引用 `graphql` 包类型，SDK 主入口导出它们时无需 graphql 安装

## 七、风险与回滚

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| `graphql` 包 parse 结果与消费端 regex 解析不一致 | 中 | 中 | 两个 parser 保持一致（已验证 schema 语法） |
| 动态 `import("graphql")` 在 ESM/CJS 混合环境失败 | 低 | 高 | 备选方案：静态 import 并将 graphql 改为 hard dependency |
| 长参数/长字段导致 markdown 表格溢出 | 中 | 低 | 列宽截断策略：`...` 省略 |
| 消费端 `ParsedSchema` 字段映射不匹配 | 低 | 中 | 设计时已对齐消费端 `FieldInfo`/`FieldArg`/`TypeFieldDef` |

**回滚策略**：若 v1.0.6 发布后发现问题，`package.json` 回退版本号，`src/codegen/` 目录整体删除，`src/index.ts` 恢复 `export * from "./codegen"` 行。
