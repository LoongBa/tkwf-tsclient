## 四、发现的问题

### 4.1 MEDIUM：onUnauthorized 应仅对 AUTH_REQUIRED 触发

**文件**：`src/tkwf.ts` 第 91-96 行、第 107-112 行

**现状**：
```typescript
try {
  return host.GetUser();
} catch (err) {
  this.getConfig(DEFAULT_SCENARIO).onUnauthorized?.();
  throw err;
}
```

**问题**：`catch` 块捕获所有异常类型，包括未来可能新增的异常（如存储访问失败）。当前 `GetUser()` 只会抛 `AUTH_REQUIRED`，所以不存在实际故障，但缺乏防御性。

**建议**：改为检查错误码，仅对 `AUTH_REQUIRED` 触发钩子：
```typescript
catch (err) {
  if (err instanceof DomainClientError && err.code === "AUTH_REQUIRED") {
    this.getConfig(DEFAULT_SCENARIO).onUnauthorized?.();
  }
  throw err;
}
```

**影响**：当前无影响，属于防御性改进。**建议修复，不阻塞发布。**

### 4.2 LOW：biome 代码风格警告

**文件**：`src/tkwf.ts`

- `noThisInStatic`（多处）：在静态方法中使用 `this` 访问静态成员。biome 警告，但项目代码库已容忍类似警告。
- `noConfusingVoidType`（第 30 行）：`onRequest` 类型签名中的 `void` 联合。与 `domain-host-client.ts` 现有签名一致。

**建议**：可忽略，与现有代码风格一致。
