## 3. 逐文件代码审查

### 3.1 `src/cache.ts`（新增，核心）

- **`RpcQueryKey`**：`readonly [scenario, sessionKey, field, variables, selection?]` 会话分桶元组——对齐 Oracle Q3 裁决（认证隔离：不同 sessionKey 数据不串）
- **`RpcQueryContext`（Oracle M1 落地）**：仅含 `signal?: AbortSignal`，删除原方案的 `fetcher`/`variableTypes` 幻影字段——TanStack `QueryFunctionContext` 无此二字段，`strictFunctionTypes` 下消费端 `useQuery({ queryFn })` 逆变检查通过
- **`RpcQueryOptions`**：单 options 对象（scenario/field/type/variables/variableTypes/selection/transport/getSessionKey）——与 `createRpcQueryKey` 共享同一组 variables/selection，防 key/fn 分叉（Oracle 复审细节 #2 已按共享 const 示例落地）
- **`createRpcQueryKey`**：`[scenario, sessionKey, field, stableSerialize(variables), selection] as const`——确定性序列化对齐 TanStack hashKey 语义（对象 key 排序、undefined 剥离、数组保序）
- **`createRpcQueryFn`**：返回 `(ctx: RpcQueryContext) => Promise<T>`，透传 field/type/variables/variableTypes/selection/sessionKey/signal 到 `transport.execute`——无事件检测逻辑（M5 落地，不实现"跳过缓存写入"）
- **`enableRpcCache<T = unknown>`（Oracle M2/M4 + S1 落地）**：
  - `QueryClient` 懒加载（`await import(QUERY_CORE_MODULE)`），`/* webpackIgnore: true */` + 变量模块名（M4）——Webpack 5 静态分析不尝试解析可选依赖
  - 未安装时抛引导错误（复用 `src/codegen/schema-parser.ts:244-252` 模板）
  - `defaultOptions.queries.retry = false`（M2，最关键）——TanStack 默认 query retry=3 会与 transport 重试形成最坏 12 次尝试，显式关闭实现单一重试归属
  - `defaultOptions.queries.staleTime` 默认 0（重取 + 去重兜底）、`gcTime` 透传
  - `getQueryClient: () => client as unknown as T`（Oracle 复审细节 #1 落地）——泛型断言，非 `as any`；`as unknown as T` 规避 TS "neither type sufficiently overlaps" 编译错误
- **`clearSession(scenario, sessionKey: string | null)`（Oracle S2/S3/S4 落地）**：先 `cancelQueries` 再 `removeQueries`（TanStack partial match 前缀匹配清空 `[scenario, sessionKey, ...]`）——防 in-flight 竞态；`sessionKey` 接受 null（guest 查询可清）；参数名 `scenario`（非 `_scenario`）
- **`stableSerialize`（Oracle S6 落地）**：对象 key 排序、undefined 剥离、数组保序、函数值原样返回（`typeof fn !== "object"` 分支）——循环引用不在支持范围（RPC variables 必须 JSON-able，文档已注明）

- **cache.test.ts（15 测试）**：
