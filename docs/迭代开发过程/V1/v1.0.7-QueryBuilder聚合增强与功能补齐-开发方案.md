> **版本**：v1.0.7
> **架构依据**：ADR17（TS QueryBuilder 增强实施修订）、ADR20（VEntity 聚合 GraphQL 自动生成）

## 1. 目标

为 ts-client QueryBuilder 补齐 ADR17 P1 规划的 6 项纯 SDK 功能，并实现 ADR20 的 TS 端聚合查询对等 API。

**两批功能合并一次迭代的原因**：
- 全部集中在 `query-builder.ts` / `query-builder-types.ts` 两个文件
- `compileGraphQL` 的 `countMode` 分支与 `aggregate` 模式分支共享同一编译管道扩展点
- 无外部依赖（无需服务端变更，SG2 已生成 `{Entity}_aggregate` resolver）

## 2. 设计

### 2.1 countAsync（ADR17 §2.2.1）

```typescript
async countAsync(): Promise<number>
```

**实现**：新增 `compileGraphQLCountMode()` 方法，编译为 `query { resolver(first: 1, where: ...) { totalCount } }`，不请求 `nodes`/`pageInfo`。复用现有 `executeAsync` 管道，从响应中提取 `totalCount`。

**技术要点**：
- `compileGraphQL` 新增 `countMode` 分支：仅请求 `totalCount`
- 复用现有 `_filters` 条件（计数查询尊重过滤条件）
- 返回 `number`，不经过 `PagedResponse`
- `invalidateCursor()` 不触发（计数不改变游标状态）

### 2.2 whereGroup（ADR17 §2.2.2）

```typescript
whereGroup(builder: (g: GroupBuilder<TFields>) => void): this
```

**新增类型** `GroupBuilder<TFields>`：

```typescript
class GroupBuilder<TFields> {
  private _mode: "and" | "or";
  private _predicates: PredicateNode<TFields>[];

  constructor(mode: "and" | "or") { this._mode = mode; }

  and(predicate: (fields: TFields) => PredicateNode<TFields>): this;
  or(predicate: (fields: TFields) => PredicateNode<TFields>): this;
  build(): object;
}
```

**实现**：
- `GroupBuilder` 构造函数接受 `mode: "and" | "or"`，决定最终 combinator
- `and()` 和 `or()` 均调用 predicate 得到 `PredicateNode`，累积到内部数组（不区分方法名，全部统一累积）
- `build()` 输出：0 条件 → `{}`；1 条件 → 单条件 `predicate.toFilter()`；N 条件 → `{ [mode]: [...] }`
- `whereGroup` 内部调用 `new GroupBuilder("and")` 创建实例（默认 AND 分组），调用回调，再 `build()` 推入 `_filters`
- 推入 `_filters` 后由 `buildWhereClause` 统一处理

**使用示例**：
```typescript
// AND 分组（默认）
.whereGroup(g => g.and(f => f.status.eq("Paid")).and(f => f.amount.gt(100)))
// → { and: [{ status: { eq: "Paid" } }, { amount: { gt: 100 } }] }

// OR 分组（需显式模式 —— 暂不提供，P1 仅 AND 模式）
// 后续可通过 whereGroup(GroupBuilder.OR, g => ...) 扩展
```

**与现有 `where` 自动 AND 语义不冲突**：`whereGroup` 产生的是单条嵌套 filter 对象。

### 2.3 clone（ADR17 §2.2.3）

```typescript
clone(): QueryBuilderBase<TEntity, TFields, TOrderByFields, TSelectFields>
```

**深拷贝范围**：
| 字段 | 拷贝策略 |
|------|---------|
| `_filters` | `[...this._filters.map(f => ({...f}))]` |
| `_sorts` | `[...this._sorts.map(s => ({...s}))]` |
| `_fields` | `[...this._fields]` |
| `_page` / `_pageSize` | 标量直接复制 |
| `_afterCursor` / `_latestCursor` | 字符串直接复制 |
| `_cursorCache` | `new Map(this._cursorCache)` |
| `transport` / `resolverField` / `_sessionKey` | **共享引用**（同一 transport 实例） |

**子类兼容**：返回类型为 `this`，codegen 子类无需额外拷贝逻辑。

### 2.4 orderByField / thenByField（ADR17 §2.2.4）

```typescript
orderByField<K extends keyof TOrderByFields>(field: K, direction?: "ASC" | "DESC"): this
thenByField<K extends keyof TOrderByFields>(field: K, direction?: "ASC" | "DESC"): this
```

**实现**：
- `field` 参数类型为 `K extends keyof TOrderByFields`，编译期字段名校验
- `orderByField` 覆盖 `_sorts`（`_sorts = [{ field: String(field), desc }]`）
- `thenByField` 追加到 `_sorts`（`_sorts.push(...)`）
- 调用 `invalidateCursor()`
- `direction` 默认 `"ASC"`

### 2.5 操作符补齐（ADR17 §2.2.5）

#### 2.5.1 isNull / isNotNull

```typescript
// StringFieldOperators / NumberFieldOperators / DateFieldOperators 各新增
isNull(): PredicateNode<TFields>    // → { field: { eq: null } }
isNotNull(): PredicateNode<TFields> // → { field: { neq: null } }
```

**实现**：在 `createStringOps`、`createNumberOps`、`createDateOps` 各新增 2 个方法，编译为 `{ field: { eq: null } }` 和 `{ field: { neq: null } }`。

#### 2.5.2 字符串取反操作符

```typescript
// StringFieldOperators 新增
ncontains(val: string): PredicateNode<TFields>    // → { field: { ncontains: val } }
nstartsWith(val: string): PredicateNode<TFields>  // → { field: { nstartsWith: val } }
nendsWith(val: string): PredicateNode<TFields>    // → { field: { nendsWith: val } }
```

**实现**：`createStringOps` 新增 3 个方法，操作符名直接映射到 HC `ncontains`/`nstartsWith`/`nendsWith`。

### 2.6 聚合查询 Aggregate（ADR20）

#### 2.6.1 AggregateResponse 类型

```typescript
class AggregateResponse {
  _count: number;
  _sum?: Record<string, number>;
  _avg?: Record<string, number>;
  _min?: Record<string, number>;
  _max?: Record<string, number>;
}
```

#### 2.6.2 AggregateFieldsBuilder

```typescript
class AggregateFieldsBuilder<TFields> {
  private _sumFields: string[] = [];
  private _count = false;
  private _avgFields: string[] = [];
  private _minFields: string[] = [];
  private _maxFields: string[] = [];

  sum(selector: (fields: TFields) => any): this;
  count(): this;
  avg(selector: (fields: TFields) => any): this;
  min(selector: (fields: TFields) => any): this;
  max(selector: (fields: TFields) => any): this;
  build(): { sum?: string[]; count?: boolean; avg?: string[]; min?: string[]; max?: string[] };
}
```

**实现**：字段名通过字段代理提取（同 `createOrderByProxy` 的 Proxy 模式）。`sum(f => f.amount)` 中 `f` 是 `TFields` 的 Proxy，属性访问触发 `get` 陷阱返回字段名字符串。`build()` 返回聚合字段声明结构供 `compileGraphQL` 使用。

#### 2.6.3 aggregate() + toAggregateAsync()

```typescript
aggregate(builder: (a: AggregateFieldsBuilder<TEntity>) => void): this
async toAggregateAsync(): Promise<AggregateResponse>
```

**`compileGraphQL` 聚合模式分支**：

```graphql
query { orderView_aggregate(first: 1, where: {status: {eq: "Paid"}}) { _sum { amount } _count } }
```

**技术要点**：
- `aggregate()` 设置 `_aggregateMode = true`，调用 `builder` 填充 `_aggregateFields`
- `toAggregateAsync()` 编译聚合模式 GraphQL，执行后解析 `AggregateResponse`
- 查询字段名使用 `{resolverField}_aggregate`（Hasura 风格，与 SG2 生成一致）
- `first: 1` 固定（聚合查询不需要分页）
- 复用 `where` 条件（过滤条件照常应用）
- `invalidateCursor()` 不触发
