## 3. 逐文件代码审查

### 3.1 `src/service-proxy.ts`（核心修复）

- **`ServiceProxyOptions.variableTypesMap?`**：`Record<string, Record<string, string>>`（field → {varName → GraphQLType}），JSDoc 注明 codegen 同源生成 + Oracle S3 逐调用覆盖非预期用法
- **createUse 派发**：`const variableTypes = options?.variableTypes ?? this.variableTypesMap?.[field];`——精确对齐 selection 既有模式（L69 `options?.selection ?? selectionMap[field]`），options 覆盖优先、map 回退、未配置为 undefined
- **execute 透传**：第 7 字段 `variableTypes`，`Transport` 接口（transport.ts:56）已声明该可选字段，strict 下天然类型安全
- **向后兼容**：未配置/未命中时 `variableTypes === undefined` → transport L92 落回 `inferGraphQLType`，行为与 v1.0.9 完全一致（两个 omit 测试显式断言）

### 3.2 `src/domain-client-user.ts` + `src/domain-host-client.ts`（两级透传）

- 链路完成：`DomainHostClientOptions.variableTypesMap` → 构造存储 → **GetUser()**（L202 旁）与 **GetGuest()**（L229 旁）双路径 → `DomainClientUserOptions.variableTypesMap` → 构造存储 → `Use()`（L463 旁）→ `ServiceProxyOptions.variableTypesMap`
- `TkwfConfig extends DomainHostClientOptions`（tkwf.ts:22）自动继承，configure 入口零改动

### 3.3 `src/codegen/schema-parser.ts` + `index.ts`（能力提供）

- **`ParsedArg.listElemNonNull?`**：新增可选字段（向后兼容），stripWrapper 在 ListType 内层 NonNull 分支置位，parseArg 透传——修复原模型"剥离列表元素非空但丢弃"的信息损失
- **`toGraphQLTypeString`**：无损重建——非列表 `${gqlType}${isNonNull ? "!" : ""}`；列表 `[${gqlType}${listElemNonNull ? "!" : ""}]${isNonNull ? "!" : ""}`，覆盖**全部 4 种可空性组合**（Oracle 方案审核 M1 落地）
- **`buildVariableTypesMap(parsed)`**：纯函数（零 graphql import / 零 I/O），跳过空 args 操作——供消费端 g.ts 生成器输出 `operationVariableTypes`（本仓库 codegen 不产 g.ts，SDK 侧提供能力）
- **scoping**：`ParsedField` 未加字段（DTO 字段类型重建不在本迭代）；`parseField/parseFieldFromInputValue/parseGraphQLSchema` 的解构保持原样规避 noUnusedLocals
